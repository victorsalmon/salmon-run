# Domain 8: External Regression Coverage (runs last)

**Purpose**: Execute the external-repo vitest suites (Upscale-Havens + Currents-Bookkeeping) and document all failures. The salmon-orchestrator Pester suite has moved to the Functional Audit (`functional-audit.md` Phase B) — this domain is now the single place for cross-repo TypeScript regression gates.

**Trigger**: Run this survey **last** (Wave 5), after all other survey domains (1–7) have completed and filed their draft plans. This domain runs external test suites; it should not run concurrently with other domains that may introduce churn.

**Procedure**:

### Phase 0 — External vitest pre-sweep

Where available, invoke an automated cross-repo coverage sweep to run the vitest suites, capture failures, and produce structured results. If no sweep script exists, fall back to Phase A.

**Divergence**: If the automated sweep fails or cannot run (environment issues), fall back to the manual Phase A below.

### Phase A — Run external vitest suites (manual fallback)

Run both suites and document pass/fail counts in the audit log. A failure in either suite is a finding.

```powershell
# Upscale-Havens — frontend (vitest, jsdom) + backend (vitest, PGlite).
# `npm test` runs both: test:fe then test:backend.
Push-Location "C:\Repos\upscale-havens"
  $uhFe = npm run test:fe 2>&1
  $uhBe = npm run test:backend 2>&1
  Write-AlignmentAuditLog -Domain "domain-4" -Action "upscale-havens-fe" `
      -Detail ($uhFe | Select-String "Test Files|Tests " | Out-String)
  Write-AlignmentAuditLog -Domain "domain-4" -Action "upscale-havens-be" `
      -Detail ($uhBe | Select-String "Test Files|Tests " | Out-String)
Pop-Location

# Currents-Bookkeeping (currentsbk.ca) — frontend + backend + e2e stub.
# `npm test` runs all three; test:e2e is a no-op stub (Playwright not wired).
Push-Location "C:\Repos\currentsbk.ca"
  $cb = npm test 2>&1
  Write-AlignmentAuditLog -Domain "domain-4" -Action "currentsbk-ca" `
      -Detail ($cb | Select-String "Test Files|Tests " | Out-String)
Pop-Location
```

Document total pass/fail/skip counts in the audit log:
```powershell
Write-AlignmentAuditLog -Domain "domain-4" -Action "phase-complete" `
    -Detail "<N>/<M> passed, <K> skipped, <L> failed"
```

### Phase B — Document failures

For each failing test, log each failing test as a finding to the Findings Manifest via `Write-Finding`. Include the test name, failure message, and diagnosed root cause. Do not implement fixes — only diagnose and document.

If the testing environment lacks prerequisites (Docker, AWS, Swarm), log the environment gaps as a finding to the Findings Manifest — but document which tests were skipped and why.

### Phase C — Generate RunFix Deploy Plan

After all failure follow-up findings are logged, log a RUNFIX_DEPLOY-1 meta-finding to the Findings Manifest as the terminal task:

```powershell
Write-Finding -Domain domain-4 -Severity info -BlastRadius critical -Title "RunFix Deploy required after audit fixes" -Detail "N session plans were generated this cycle (see manifest summary). A RunFix Deploy session plan will be generated in Phase B." -Files @("Tasks/Code/<date>-runfix-deploy-*.md")
```

> **Note**: The RunFix Deploy session plan is generated by Phase B consolidation after all other plans are written.

**Failure handling:** for each failing test in either suite, log a finding via `Write-Finding` with the repo name, test file, test name, and the assertion error. Do NOT implement fixes — diagnose and document. Create a `Tasks/Code/` session plan for each non-trivial failure (or group related failures into one plan).

**Environment gaps:** if Node.js or npm is unavailable, or `npm install` has not been run in a repo, log the environment gap as a finding — but document which suite was skipped and why. The suites do not require Docker or AWS credentials (PGlite is in-process; the e2e stub is a no-op).
