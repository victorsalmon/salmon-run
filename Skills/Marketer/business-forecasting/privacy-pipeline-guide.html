Privacy Pipeline

Client data never reaches the AI model. Merchant names stay on the USB drive.

✓ Zero-data-promise guaranteed

Raw transaction descriptions are never read by the opencode agent. They are hashed before the agent session and restored after the session ends, on your local machine, using a lookup file that never leaves the USB drive.

Step-by-Step Workflow

Pre-process: anonymize the raw CSV

Run this on the USB drive before connecting it to the laptop with opencode.

python hash-csv.py --csv client-bank.csv --output anonymized.csv
FlagRequiredDefaultPurpose
--csvYes—Comma-separated raw CSV file paths
--output / -oNo<input>-anonymized.csvOutput anonymized CSV path
--saltNoRandom 16-byte hexReuse to produce identical hashes across runs

What it produces:

FileContainsWhere it goes
anonymized.csv row_id, date, description_hash, amount, category, type Copied to laptop for agent
anonymized-lookup.json {salt, rows: {uuid: {original_description, ...}}} Stays on USB drive

The salt is a one-time random key. Same description always produces the same hash (recurring detection works). Without the salt, the hash cannot be reversed.

Run the forecast (agent session)

The agent on the laptop reads only the anonymized CSV. It never sees merchant names.

python income-forecast.py --csv anonymized.csv --balance 25000 --horizon 365 --row-ids
FlagPurpose
--row-idsEmit a row_ids column linking each forecast event to its source transaction UUIDs

Without --row-ids, the output is identical to before — no traceability needed if you don't require restoration.

The output forecast.csv contains hashed descriptions for recurring patterns. The agent can still give business advice based on categories and amounts.

Post-process: restore original descriptions

Run this on the USB drive after copying the forecast back from the laptop.

python rename-csv.py --forecast forecast.csv --lookup anonymized-lookup.json
FlagRequiredDefaultPurpose
--forecastYes—Forecast CSV from income-forecast.py --row-ids
--lookupYes—Lookup JSON from hash-csv.py
--output / -oNo<forecast>-restored.csvOutput restored CSV path

What changes:

ColumnBeforeAfter
description9e3d2d63ca43... (hash)Client A Payment (original)
row_idsuuid1,uuid2,...Replaced with original_descriptions

Aggregate rows (spontaneous estimates, balance forward) have no UUIDs and pass through unchanged.

How It Works

Description Hashing

Each transaction description is hashed with:

SHA-256(salt + description)

The result is a full 64-character hex string. Because the salt is random per session:

  • Same merchant, same session → identical hash (recurring detection works)
  • Cross-session → different hashes (no correlation between sessions)
  • Irreversible → without the salt, the original cannot be recovered

UUID Traceability

Every input row gets a UUID v4. The lookup JSON on the USB drive maps each UUID to:

  • Original description
  • Original date
  • Original amount
  • Original category and type

When income-forecast.py --row-ids detects a recurring pattern, it collects the UUIDs of all source transactions. The forecast CSV carries these UUIDs. rename-csv.py uses them to restore the original descriptions.

What Stays On the USB Drive

These files never go to the laptop:

  • raw-bank-*.csv — original bank data
  • *-lookup.json — UUID-to-original mapping + salt
  • *-restored.csv — the final output with restored descriptions

What the Agent Sees

The agent on the laptop only has access to:

  • anonymized.csv — dates, amounts, categories, hashed descriptions, UUIDs
  • forecast.csv — the same hashed descriptions in the output

No merchant names. No client names. No PII.

Multiple Input Files

Both engines accept comma-separated file lists. All files are merged into a single anonymized output:

python hash-csv.py --csv 2025.csv,2026-Q1.csv,2026-Q2.csv --output merged-anonymized.csv

Deterministic Re-Hashing

Use --salt to produce the same hashes across runs (useful if you re-anonymize the same data):

python hash-csv.py --csv client-bank.csv --output anonymized.csv --salt a1b2c3d4e5f6a7b8

Without --salt, a new random salt is generated each run → different hashes each time.

FAQ

Can I skip anonymization?

Yes. Omit hash-csv.py and don't use --row-ids. The engine works identically without them. The privacy pipeline is optional — add it when clients need assurance.

Does hashing break recurring detection?

No. SHA-256 is deterministic: "Starbucks Coffee" always produces the same hash for the same salt. The engine groups identical hashes as recurring patterns — just like it groups identical merchant names.

Is SHA-256 secure enough?

Yes. SHA-256 is a NIST-approved cryptographic hash. With a 128-bit random salt, rainbow-table attacks are infeasible. The hash alone cannot be reversed.

What about amounts and dates?

Dates and amounts are passed through unchanged. They are not PII — they are necessary for the Monte Carlo engine and do not identify individuals. Only the description column contains merchant/client names.

What if I need to re-anonymize the same data?

Pass the same --salt to produce identical hashes. The salt is printed at the end of each hash-csv.py run. Save it with the lookup file.
